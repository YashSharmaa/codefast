# Schedule files and exclusion rules

Next, I want to keep a schedule in a text file, and to leave out a whole series of dates from a schedule, not only single dates.

## Interface changes

- `Schedule.exclude_rule(rule: Rule | str) -> None`: a string is parsed with `parse_rule`. Every occurrence of that rule, expanded from the schedule's start with its own `COUNT` and `UNTIL`, is never produced by the schedule, whatever produced it (a rule or an extra date). This holds for `between` and `next_after`.
- New module `recur/calfile.py` with `load_schedule(text: str) -> Schedule` and `dump_schedule(schedule: Schedule) -> str`. `recur/__init__.py` re-exports both.
- The `schedule` command takes `--exrule RULE`, repeatable, each passed to `exclude_rule`.
- New command `file PATH --from DATE --to DATE`: reads the schedule file at PATH and prints the dates of `between(from, to)`, one per line.
- New command `format PATH`: reads the schedule file at PATH and writes the text of `dump_schedule` to stdout exactly as it is, with no extra empty line.

## The file format

The text is read line by line. Whitespace at both ends of a line is ignored. Then empty lines and lines that start with `#` are skipped. Every other line is `NAME:VALUE`, split at the first `:`. The name is case-insensitive, and whitespace around the name and around the value is ignored. The names are:

- `START`: the schedule's start date. Required, exactly once, on any line of the file.
- `RULE` and `EXRULE`: a rule text, given to `add_rule` or `exclude_rule`.
- `ADD` and `EXCLUDE`: one date or a comma list of dates (whitespace around each date is ignored), each given to `add_date` or `exclude`.

`RULE`, `EXRULE`, `ADD` and `EXCLUDE` may appear any number of times and in any order, before or after `START`. Dates are read with `parse_date`.

`load_schedule` raises `RuleError` for a line without `:`, an unknown name, a second `START` line, a bad date and a bad rule. The message of each of these starts with `line N: `, where N is the number of the offending line in the text (for a second `START`, the line of that second one), counting from 1 and counting empty and comment lines too. A text without a `START` line also raises `RuleError`.

`dump_schedule` writes the canonical file. First `START:<date>`, then one `RULE:<canonical text>` line per rule in the order the rules were added, then one `EXRULE:<canonical text>` line per exclusion rule in the order they were added, then one `ADD:<date>` line per extra date and one `EXCLUDE:<date>` line per excluded date, both ascending and without duplicates. There are no spaces and no comments, and every line ends with a newline. Example:

```
START:2026-01-01
RULE:FREQ=WEEKLY;BYDAY=MO
EXRULE:FREQ=MONTHLY;BYDAY=1MO
ADD:2026-01-20
EXCLUDE:2026-01-19
```

So `load_schedule(dump_schedule(s))` produces the same dates as `s`. On the command line, a file that cannot be read is reported like a `RuleError`: one line `error: <message>` on stderr and exit status 2. Files are read as UTF-8.
