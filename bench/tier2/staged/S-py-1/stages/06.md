# Bug: spaces inside a rule are rejected

People paste rules with spaces in them, and they fail. `parse_rule("FREQ=WEEKLY; BYDAY=MO, FR")` raises `RecurError` about an unknown key ` BYDAY`. It should give the same rule as `parse_rule("FREQ=WEEKLY;BYDAY=FR,MO")`. My first message only said that whitespace at both ends of the whole text is ignored, and that is not enough.

## Interface changes

None. Only `parse_rule` changes, and everything that uses it follows: `Schedule.add_rule`, `Schedule.exclude_rule`, schedule files and the command line.

## What should happen

Whitespace (spaces and tabs) is ignored around each part between `;`, around the key, around the value, and around each item of a comma list. So all of these give the same rule as `FREQ=MONTHLY;BYDAY=-1FR,MO;COUNT=3`:

- `FREQ=MONTHLY; BYDAY=-1FR,MO; COUNT=3`
- `FREQ = MONTHLY ; BYDAY = -1FR , MO ; COUNT = 3`
- `freq=monthly;` then a tab, then `byday=mo,` then a tab, then `-1fr;count=3`

Whitespace inside a key, a number, a weekday code with its ordinal, or a date is still an error, with the key it belongs to: `BY DAY=MO` is an unknown key with key `BY DAY`, `COUNT=1 0` has key `COUNT`, `BYDAY=2 TU` has key `BYDAY`, `UNTIL=2026-01- 05` has key `UNTIL`.

A part that is empty or only whitespace is still an error with key `None`, as in `FREQ=DAILY; ;COUNT=2`. A value or list item that is empty or only whitespace is still an error with the key it belongs to: `FREQ=DAILY;COUNT= ;INTERVAL=2` has key `COUNT` and `FREQ=WEEKLY;BYDAY=MO, ,FR` has key `BYDAY`.

An unknown key is reported without the whitespace around it: `FREQ=DAILY; COLOR = red` has key `COLOR`. Canonical text from `to_text` never contains whitespace.
