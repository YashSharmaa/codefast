# Fuzz when applying

Next, I want `apply` to cope with context lines that have changed in the target text, the way `patch --fuzz` does. A hunk that does not fit may then be placed with some of its outer context lines left out.

## Interface changes

- `Applied` gets a third field: `pub struct Applied { pub text: String, pub offsets: Vec<isize>, pub fuzz: Vec<usize> }`. `fuzz` holds one value per hunk, in order.
- New `apply::apply_patch_fuzzy(text: &str, patch: &Patch, max_fuzz: usize) -> Result<Applied, Error>`, re-exported at the crate root. `apply_patch(text, patch)` gives the same result as `apply_patch_fuzzy(text, patch, 0)`, so its `fuzz` values are all 0.
- The command becomes `patchwork apply FILE PATCH [-F N]`, with N a non-negative decimal number, 0 when the option is absent. An invalid N prints `error: invalid fuzz: <N>` and exits 2. Any other extra argument, or `-F` without N, is a usage error.

## Behaviour

The leading context of a hunk is the run of `Context` lines at the start of its lines, and its trailing context is the run of `Context` lines at its end. When every line of a hunk is `Context`, all of them are leading context and the trailing context is empty.

Hunks are still placed in order. Each one is first tried with fuzz 0, which is exactly the stage 1 rule. If no position is allowed, it is tried with fuzz 1, then 2, and so on up to `max_fuzz`, and the first fuzz that works is used. At fuzz f the hunk is shortened: its first min(f, leading) lines and its last min(f, trailing) lines are dropped. The shortened hunk is then placed with the stage 1 rules, where:

- its old lines and new lines are those of the shortened hunk,
- its nominal position is the nominal position of the whole hunk plus the number of dropped leading lines,
- its offset is k minus that shortened nominal position, and this offset is the one the next hunk adds to its own nominal position,
- the lines it replaced end at k plus the number of its old lines.

Dropped lines are neither compared nor changed, so the text keeps whatever it has in their place. If no fuzz up to `max_fuzz` works, the error is `Error::HunkFailed(i)` as before. `fuzz` records the fuzz each hunk was placed with.

For example, the hunk ` a`, `-b`, `+B`, ` c` with header `@@ -1,3 +1,3 @@` does not fit `A\nb\nc\n`. With fuzz 1 both `a` and `c` are dropped, `b` is found at index 1, and the result is `A\nB\nc\n` with offset 0 and fuzz 1.

On the command line, for each hunk in order, stderr gets `hunk <i> offset <k> fuzz <f>` when its fuzz is not 0, and as before `hunk <i> offset <k>` when its fuzz is 0 and its offset is not.
