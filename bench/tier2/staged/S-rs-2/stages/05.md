# Ignoring whitespace

Next, I want diffs and merges that can ignore changes in spaces and tabs, like `diff -Z` and `diff -w`. The functions that compare lines get a new parameter for it.

## Interface changes

- New in module `diff`, re-exported at the crate root: `#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub enum Whitespace { Exact, IgnoreTrailing, IgnoreAll }`.
- These functions get a new last parameter `ws: Whitespace`, and every caller in the project, the tests included, must pass one:
  - `diff_lines(old: &[String], new: &[String], ws: Whitespace) -> Vec<Edit>`
  - `make_patch(old_name: &str, old_text: &str, new_name: &str, new_text: &str, context: usize, ws: Whitespace) -> Patch`
  - `merge3(base: &str, ours: &str, theirs: &str, ws: Whitespace) -> Merged`
- `Whitespace::Exact` gives exactly the behaviour so far.
- Command line: `patchwork diff OLD NEW [-U N] [-Z | -w]` and `patchwork merge BASE OURS THEIRS [-Z | -w]`. `-Z` selects `IgnoreTrailing`, `-w` selects `IgnoreAll`, and without either the rule is `Exact`. The options after the file arguments may come in any order, and they apply to directory diffs too. An option given twice, both `-Z` and `-w`, `-U` without N, `-U` for `merge`, or any other extra argument is a usage error. An invalid N still gives `error: invalid context: <N>`.

## Behaviour

Under a rule, two lines are equal when they are equal after this change to both. With `IgnoreTrailing`, the spaces and tabs at the end of the line are removed (right before its `\n`, or at the very end of a last line without one). With `IgnoreAll`, every space and tab is removed. Nothing else changes: the `\n` still counts, so `"b"` and `"b\n"` stay different under every rule, and other characters such as `\r` count too.

`diff_lines` keeps all its stage 1 rules, with equal lines meaning lines equal under the rule, and minimal counted the same way. An `Equal` edit carries the old line. So the context lines of a patch made with a rule hold the old text, and whitespace-only differences outside the changed lines appear nowhere in the patch. `apply` is unchanged and always compares lines exactly.

`merge3` uses the rule for both of its diffs. So a line that differs from the base only in ignored whitespace counts as unchanged, and the merged text has the base line there. When both sides change a group, their two versions are compared under the rule too: they are equal when they have the same number of lines and each pair of lines is equal under the rule. Then the ours version is written and there is no conflict.
