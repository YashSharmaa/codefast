# GNU style headers and patches for whole trees

Next, I want patchwork to work with what `diff -ru` writes: patches for whole directory trees, with the short hunk headers GNU diff uses.

## Interface changes

- New `patch::parse_patches(text: &str) -> Result<Vec<Patch>, Error>` and `patch::format_patches(patches: &[Patch]) -> String`, re-exported at the crate root.
- `format_patch` writes a count of 1 in a new way (below), which changes what `diff` and `reverse` print.
- `stat` and `reverse` now read PATCH with `parse_patches`, and `diff` also accepts two directories. `apply` still reads exactly one file patch with `parse_patch`.

## Short hunk headers

This replaces two rules of the unified diff section. GNU diff leaves out a count of 1, so a one-line change is `@@ -5 +5 @@`, not `@@ -5,1 +5,1 @@`.

- `format_patch` writes each side of a header as `<start>,<count>` as before, except that a count of exactly 1 is written as just `<start>`. The two sides are handled separately. So old count 2 and new count 1 at line 3 give `@@ -3,2 +3 @@`, one line added to an empty text gives `@@ -0,0 +1 @@`, and deleting the only line gives `@@ -1 +0,0 @@`.
- `parse_patch` reads each side of a header either as `S,C` or as `S` alone, which means a count of 1. The parsed `Hunk` holds the count 1 either way, and its body is read with that count. So `@@ -1,1 +1 @@` is the same as `@@ -1 +1 @@`. A start of 0 still needs a count of 0, so `@@ -0 +1 @@` is invalid. A comma must be followed by a number, so `@@ -1, +1 @@` is invalid, and so are `@@ - +1 @@` and `@@ -,1 +1 @@`.

## Several files

A patch for several files is file patches written one after another, each in the stage 1 form. `parse_patches` reads one or more of them. Where a hunk header is expected (after a `+++ ` line or after a complete hunk body), a line starting with `--- ` starts the next file patch, and its next line must start with `+++ `. Inside a hunk body the counts decide as before, so a line `--- x` there is a removed line. Error line numbers count from the start of the whole text, and an empty text is an error at line 1. `parse_patch` still reads one file only, so for it a second `--- ` line is an invalid hunk header. `format_patches` concatenates the `format_patch` output of the patches in order, and is empty for no patches.

`stat` prints its line for each file patch, in order. `reverse` prints `format_patches` of all the file patches reversed, in order.

## Directories

When OLD and NEW are both directories, `diff` compares the two trees. It collects the relative paths of all regular files under either directory, at any depth, with `/` between the parts, and sorts them as strings in byte order. For each path the names are `OLD/<path>` and `NEW/<path>` (the argument as given, then `/`, then the path), and a file missing on one side counts as an empty text. So an empty file that exists on one side only gives no patch. Each pair is diffed like two single files with the same `-U`, and the patches that have hunks are printed with `format_patches`. The exit code is 1 when something was printed and 0 otherwise.

If only one of OLD and NEW is a directory, or a path is a file on one side and a directory on the other, reading the directory as a file fails with `error: cannot read <path>` and exit 2. The path is the argument as given for OLD or NEW, or `OLD/<path>` or `NEW/<path>` inside the trees.
