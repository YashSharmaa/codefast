# Three-way merge

Next, I want patchwork to merge two edited versions of the same text, the way `git merge-file` does.

## Interface changes

- A new public module `merge` (file `src/merge.rs`), declared in `src/lib.rs`, with its items re-exported at the crate root: `#[derive(Debug, Clone, PartialEq, Eq)] pub struct Merged { pub text: String, pub conflicts: usize }` and `merge::merge3(base: &str, ours: &str, theirs: &str) -> Merged`.
- A new command `patchwork merge BASE OURS THEIRS`. It reads the three files and prints the merged text exactly (no extra newline). Without conflicts it exits 0 with nothing on stderr. With conflicts it prints `conflicts: <n>` to stderr and exits 1. If a file cannot be read, the first one in the order BASE, OURS, THEIRS gives `error: cannot read <path>` with exit 2. Any other number of arguments is a usage error.

## Behaviour

`merge3` splits the three texts into lines and computes `diff_lines(base, ours)` and `diff_lines(base, theirs)`. In each script, every maximal run of non-`Equal` edits is one change. A change replaces the base lines `s .. e` (0-based indices, e excluded) with its `Insert` lines. Here s is the number of `Equal` and `Delete` edits before the run, and e is s plus the number of `Delete` edits in it. A pure insertion has s equal to e.

Two changes touch when s1 <= e2 and s2 <= e1. So overlapping changes touch, a change that ends at index 2 touches one that starts at 2, and an insertion at s touches a change that starts or ends at s. The changes of both sides are put into groups: two changes that touch are in the same group, and so on transitively. A group covers the base lines from the smallest s to the largest e of its changes.

The merged text is built from the start of the base. Base lines outside every group are copied. For each group, a side's version is the base lines the group covers with that side's changes in the group applied. If only one side has changes in the group, its version is written. If both have and the two versions are equal, that version is written once. Otherwise the group is a conflict, and the merged text gets the line `<<<<<<< ours`, the ours version, the line `=======`, the theirs version and the line `>>>>>>> theirs`. Each marker line ends in `\n`. When the merged text so far is not empty and does not end in `\n` (because a version's last line has none), a `\n` is added before the marker. `conflicts` is the number of conflicting groups.

For example, with base `a\nb\nc\nd\n`, ours `a\nB\nc\nd\n` and theirs `a\nb\nc\nD\n`, the changes do not touch and the result is `a\nB\nc\nD\n` without conflicts. If theirs is `a\nb\nC\nd\n` instead, ours replaces `1 .. 2` and theirs replaces `2 .. 3`, so they touch, and the result is:

```
a
<<<<<<< ours
B
c
=======
b
C
>>>>>>> theirs
d
```
