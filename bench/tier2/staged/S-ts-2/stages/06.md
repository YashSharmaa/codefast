# Bug: emoji count as two characters

With the data `{"s": "naïve 😀"}`, `{{ s | length }}` gives 8 and `{{ s | last }}` outputs half of the emoji (a lone surrogate). `{{ "😀😀" | truncate(1) }}` gives a broken character followed by `...`, and `{% for c in s %}` runs 8 times. The text has 7 characters, so these should give 7, `😀`, `😀...` and 7 iterations.

## What changes

Wherever a string is taken apart into characters, a character is now one Unicode code point, not one UTF-16 code unit. A surrogate pair is one character. This applies to:

- `length` of a string.
- `first` and `last` of a string.
- `truncate(n)`: a string of at most n characters is kept, otherwise the result is its first n characters followed by `...`.
- `for` over a string, with one or two loop variables: the characters, the indexes (counted in characters) and everything in `loop`.

A character is a code point, not what a reader sees as one letter. So `e` followed by U+0301 COMBINING ACUTE ACCENT is still two characters.

Nothing else changes. Comparisons of strings and `sort` still use UTF-16 code unit order, `in` and `replace` work on substrings as before, `upper`, `lower` and `trim` are unchanged, and `length`, `first` and `last` of arrays are unchanged.
