# Macros, calls, imports and globals

Next, I want reusable pieces of markup. Please add macros in a new module `src/macros.ts`, calls in expressions, call blocks, imports of macros from other templates, and global values.

## Interface changes

- New file `src/macros.ts` exporting `class Macro`. Every macro value is an instance of it, with `name: string` and `params: string[]` (the parameter names in order).
- `EnvironmentOptions` gains `globals?: Record<string, unknown>`, and `Environment` gains `addGlobal(name: string, value: unknown): void`, which adds or replaces one global.
- New statements `macro` and `endmacro`, `call` and `endcall`, `import`, and `from ... import`. A call `(args)` becomes an atom suffix, like `.segment` and `[expr]`.

## Globals

A name that no loop variable, `set` variable or data property defines is looked up in the globals before it is `undefined`. Every template sees the globals, including included and imported templates and macro bodies.

## Macros

`{% macro name(a, b = expr) %} body {% endmacro %}` defines a macro with parameters that are names (not keywords), each with an optional default. These are `TemplateSyntaxError`s: a repeated parameter, a parameter without a default after one with a default, missing parentheses, text after the `)`, a keyword as the macro name, and `endmacro` without `macro`. An `else` directly in a macro body is an `else` without `if` or `for`. The tag outputs nothing. When it is rendered it stores the macro under its name as `set` would, so it can be called from the tags after it, and it can call itself.

The body sees its parameters, then the variables visible where the macro tag was rendered, then the data and globals of that render. It does not see the variables of the place it is called from. Each call has its own scope, like an included template, so a `set` in the body lasts until the end of that call.

## Calls

`f(1, x, k = v)` passes positional arguments, then keyword arguments. A positional argument after a keyword argument, a repeated keyword or a trailing comma is a `TemplateSyntaxError`.

- Calling a macro binds the positional arguments to the parameters in order, then the keyword arguments by name. Arguments are passed as they are, so a value marked by `raw` stays unescaped in the body. Too many positional arguments, an unknown keyword or a parameter given twice is a `RenderError`. A parameter without an argument gets its default, evaluated at each call in the body's scope with the earlier parameters bound, or `undefined` when it has no default.
- The result of a macro call is the rendered body marked safe as by `raw`: `{{ }}` does not escape it again, and a filter receives it as a plain string.
- Calling a JavaScript function (from the data or the globals) passes the positional arguments as plain values and gives its return value as is. Keyword arguments for a function are a `RenderError`, and an exception it throws propagates unchanged.
- Calling anything else (including `undefined`) is a `RenderError`, and so is outputting a macro or a function with `{{ }}`.

## Call blocks

`{% call m(args) %} body {% endcall %}` calls the macro m with these arguments and outputs the result. During that call the macro body sees `caller`, which renders the call block's body when called with no arguments, with the variables visible at the call block, and gives the text marked safe. Calling `caller` with arguments is a `RenderError`. A body that never calls `caller` is never rendered. A `call` tag whose expression is not a call, and `endcall` without `call`, are `TemplateSyntaxError`s. A callee that is not a macro is a `RenderError`.

## Imports

`{% import "name" as ns %}` renders the template name with no data variables (globals are still seen) and drops its output. It then stores under ns an object whose properties are the top-level variables of that template that hold macros (top level as for `set`, so also inside `if`), and these macros see that template's top-level variables. `{% from "name" import a, b as c %}` renders the template in the same way and stores its macro a under a and its macro b under c. A name that is not such a macro is a `RenderError`. Both tags output nothing and store like `set`. The template name must be a string literal and the other names must be names that are not keywords, otherwise it is a `TemplateSyntaxError`. An unknown template, or one that is already being rendered, is a `RenderError` as for includes.
