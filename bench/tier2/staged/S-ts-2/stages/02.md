# Computing values: arithmetic, lists, objects and `set`

Next, I want templates to compute values instead of only showing them. Please add arithmetic and string concatenation, list and object literals, subscripts, and a `set` statement.

## Interface changes

No new exports. The expression language and the statements grow as described below. Everything not mentioned here stays as specified.

## Operators

The order from loosest to tightest is now: `or`, `and`, `not`, comparisons, `~`, then `+` and `-`, then `*`, `/`, `//` and `%`, then unary `-`, then filters, then atoms with their suffixes. Binary operators of one level group from left to right, so `10 - 3 - 2` is 5 and `'a' ~ 1 + 2` is `a3`. Filters bind tighter than every operator, so `a + b | length` is `a + (b | length)` and `-x | round` is `-(x | round)`.

- `a + b` adds two numbers, joins two strings, or gives a new array with the elements of two arrays. Any other pair is a `RenderError`.
- `-`, `*`, `/`, `//` and `%` need two numbers, else `RenderError`. `/` is JavaScript division, `a // b` is `Math.floor(a / b)` and `a % b` is `a - b * Math.floor(a / b)`, so `-7 // 2` is -4 and `-7 % 3` is 2. A right side of 0 for `/`, `//` or `%` is a `RenderError`.
- Unary `-x` needs a number, else `RenderError`.
- `a ~ b` turns both sides into text as `{{ }}` would, without escaping, and joins them. So `missing ~ 'x'` is `x`, and an object that is not an array is a `RenderError`. The result is an ordinary string, so `{{ }}` escapes it.
- Operands marked by `raw` are used as their plain value, and every result is an ordinary value.

A `-` directly followed by a digit is still part of a number literal, except when the token before it ends a value: a number, a string, a path segment, a name other than `and`, `or`, `not` and `in`, or a closing `)`, `]` or `}`. Then it is the minus operator. So `a-1`, `a -1` and `a - 1` all subtract, `a - -1` adds 1, and `-2.5 | round` is the literal -2.5 rounded.

## Literals and subscripts

Atoms gain list literals `[a, b]` and object literals `{"k": v, "j": w}`. Object keys must be string literals, and a later key replaces an earlier one. `[]` and `{}` are empty. A trailing comma, a missing `:` or a key that is not a string literal is a `TemplateSyntaxError`. Each evaluation gives a new array or object, so `[1] == [1]` is false. Since `}}` ends a tag, write a space between two closing braces.

Any atom can be followed by any number of suffixes. `.segment` works as for paths. `x[expr]` evaluates expr: on an array, an integer number of at least 0 picks that element. On another non-null object, a string picks an own property. Everything else is `undefined`, so `xs['0']`, `xs[-1]` and `o[1]` are `undefined`.

## `set`

`{% set name = expr %}` evaluates expr and stores the value under name, and outputs nothing. Spaces around the `=` are optional. The name must be a name that is not a keyword, and any other form (`{% set x %}`, `{% set x == 1 %}`, `{% set 1 = 2 %}`) is a `TemplateSyntaxError`. The variable hides data and outer variables of the same name in the tags that follow, until its scope ends:

- `if` does not open a scope. At the top level, the variable lasts until the end of the template being rendered, and templates included later see it.
- In a `for` body it lasts until the end of that iteration. So `{% set t = 0 %}{% for x in [1, 2] %}{% set t = t + x %}{{ t }}{% endfor %}{{ t }}` gives `120`. Setting a loop variable changes it for the rest of that iteration.
- An included template has its own scope, so its `set` variables are gone when the include ends.
