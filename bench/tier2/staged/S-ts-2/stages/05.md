# Errors say where they happened

When a render fails deep inside an include or a macro I cannot tell where. Next, I want every template error to carry the template name and the line, and the error constructors to take a location object instead of a bare line.

## Interface changes

In `src/errors.ts`, replacing `new TemplateSyntaxError(message, line)` and `new X(message)`:

```ts
export type ErrorLocation = { template?: string | null; line?: number | null };
class TemplateError extends Error {
  template: string | null; // null when unknown
  line: number | null; // 1-based, null when unknown
  constructor(message: string, location?: ErrorLocation); // a missing field is null
  describe(): string;
}
class TemplateSyntaxError extends TemplateError {
  constructor(message: string, location: { template?: string | null; line: number });
}
class RenderError extends TemplateError {} // constructed like TemplateError
```

Update every place that builds these errors, and your own tests. `message` is now the bare message without any location in it. `describe()` gives `TEMPLATE:LINE: MESSAGE` when both are known, `TEMPLATE: MESSAGE` with only a template, `line LINE: MESSAGE` with only a line, and the message alone otherwise.

## Which location

- The template name is the name the source came under: the key in `templates`, the name given to `addTemplate`, or the name asked from `loader`. The source of `renderString` has the template `null`.
- A `TemplateSyntaxError` has the line of the offending tag, as before, and the template being parsed.
- A `RenderError` gets the line on which the failing tag starts and the template whose source holds that tag. The failing tag is the `{{ }}` tag or the statement tag being evaluated (for a failing `elif` condition, the `elif` tag). For an error inside an included template, a macro body or a call block body, it is the innermost such tag. A macro body belongs to the template that defines the macro, and a call block body to the template of the call block. An error while binding macro arguments, including evaluating defaults, belongs to the tag with the call.
- An include, import or `from` import of an unknown template, or one that would make a cycle, belongs to that tag, and so does a `from` import of a name that is not a macro. `render` of an unknown name has template and line `null`.
- A `RenderError` thrown by a custom filter or function gets the location of the tag when its line is `null`. A `RenderError` that already has a line, and any other exception, propagate unchanged.

## Command line

Every `TemplateError` now prints `error: ` followed by `describe()`, as one line on stderr, with exit status 1. The templates are named as the environment sees them: the template given on the command line by its file name without the directory, and included or imported templates by the names written in the tags. So a syntax error on line 3 of `dir/bad.txt` prints `error: bad.txt:3: ` followed by the message. Other failures print `error: <message>` as before.
