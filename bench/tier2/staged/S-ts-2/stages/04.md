# Loops over more kinds of values, and loop control

Next, loops. Some values that are errors in a `for` today should loop, and I want filtered loops, more `loop` variables, `break` and `continue`, and number ranges.

## Interface changes

No new exports. There is a built-in global function `range`, which a global or data variable named `range` hides. New statements `{% break %}` and `{% continue %}`, and a `for` tag may end with `if condition`.

## What can be looped over

This replaces the stage 1 rule that one loop variable needs an array and two need an object:

- One variable over an array gives its elements, over a string its characters in order, and over another non-null object its own property names in insertion order.
- Two variables over an object give each property name and value, as before. Over an array they give the index (from 0) and the element, and over a string the index (from 0) and the character.
- `null` and `undefined` work as before. Any other value (a number, a boolean, a function) is still a `RenderError`.

## Filtered loops

`{% for x in xs if cond %}` keeps only the items for which cond is truthy. The condition is evaluated once per item, before the body runs, with the loop variables bound, and it does not see this loop's `loop` (a `loop` from an outer loop is seen). Everything else works on the kept items only: `loop` counts them, and the `else` part runs when no item is kept. `if` with no condition, or anything else after the expression, is a `TemplateSyntaxError`.

## The `loop` variable

`loop` also holds:

- `revindex`: the number of items from this one to the end, so `length` in the first iteration and 1 in the last. `revindex0` is `revindex` minus 1.
- `depth`: 1 for a loop with no enclosing loop, otherwise the `depth` of the enclosing loop plus 1. A loop in an included template is inside the loop that the include is in.
- `previtem` and `nextitem`: what the last loop variable holds in the previous and in the next iteration, and `undefined` in the first and in the last.

## `break` and `continue`

`{% break %}` ends the innermost loop at once and keeps the output so far. `{% continue %}` ends the current iteration, keeping its output so far, and goes on with the next item. Both take nothing after the word. Each must be in the body of a `for` of the same template: the nearest enclosing `for`, `macro` or `call` tag (`if` does not count) must be a `for`, and the tag must not be in its `else` part. Otherwise it is a `TemplateSyntaxError` when the template is parsed, so an included template or a macro body cannot stop a loop it is rendered from.

## `range`

`range(stop)`, `range(start, stop)` and `range(start, stop, step)` take integers and give an array of numbers from start (default 0) up to stop, without stop, by step (default 1). A negative step counts down, so `range(5, 0, -2)` is `[5, 3, 1]`, and `range(3, 1)` is empty. A step of 0, fewer than one or more than three arguments, or an argument that is not an integer is a `RenderError`.
