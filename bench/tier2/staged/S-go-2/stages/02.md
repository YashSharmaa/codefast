# Fixed windows

Some partners count their quotas in fixed windows ("100 requests a minute, and the counter starts again every minute"), and I want policies that behave the same way. Please add a fixed-window limiter next to the token bucket and let each policy choose.

## Interface changes

```go
// new package window
type Window struct { /* unexported */ }
func New(limit int, length time.Duration, now time.Time) *Window
func (w *Window) Available(now time.Time) int
func (w *Window) Take(now time.Time) bool
func (w *Window) RetryAfter(now time.Time) int

// package policy: Policy gets one more field, after By
Algo string // "bucket" (the default) or "window"
```

`Policy` still has exactly its listed fields.

## Windows

A `Window` counts the tokens taken in its current window. Windows have the given length and are aligned to the creation time: the first starts at the `now` given to `New`, the next exactly one length later, and so on. Each method first checks the time: when `now` is at or after the end of the current window, the current window becomes the one that contains `now`, with nothing taken yet. A `now` before the end of the current window, even one before its start, stays in the current window. Then:

- `Available` returns the limit minus the tokens taken in the current window.
- `Take` takes one token and returns true when one is available, otherwise it changes nothing and returns false.
- `RetryAfter` returns 0 when a token is available. Otherwise it returns the time from `now` to the end of the current window in whole seconds, rounded up, and 1 when that is less than 1.

## Policies, engine and server

A new OPTION, `algo=bucket` or `algo=window`. Any other value, or a second `algo=`, is `bad option`, and a line may now have up to 8 fields (the field count rule becomes "fewer than 5 or more than 8"). A window policy takes no burst: `burst=` together with `algo=window`, in either order, is `bad option`, and the `Burst` field of a window policy is its limit.

For each key of a window policy the engine keeps a `Window` instead of a `Bucket`, created at the first check that sees the key, and uses it exactly as a bucket: a policy denies when no token is available, an allowed request takes one token, and `RetryAfter` and `Remaining` come from the window's `RetryAfter` and `Available`. In `GET /policies` each object gets an `"algo"` key after `"by"`, for example `{"name":"q","methods":"GET","pattern":"/q","limit":100,"window_seconds":60,"burst":100,"by":"ip","algo":"window"}`.
