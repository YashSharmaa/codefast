# Request costs

Some endpoints are much more expensive than others, and I want an upload to use up five tokens where a read uses one. That means a limiter must be able to take more than one token at a time, so please change the limiter methods and add a cost to policies.

## Interface changes

```go
// package bucket, replacing Take(now) and RetryAfter(now)
func (b *Bucket) Take(now time.Time, n int) bool
func (b *Bucket) RetryAfter(now time.Time, n int) int

// package window, replacing Take(now) and RetryAfter(now)
func (w *Window) Take(now time.Time, n int) bool
func (w *Window) RetryAfter(now time.Time, n int) int

// package policy: Policy gets one more field, after Algo
Cost int // tokens one matching request takes, 1 when not given
```

The old one-argument methods go away. Update every caller, your own tests included. `Available` does not change.

## Limiters

For a bucket, `Take(now, n)` removes n tokens (n × W units) and returns true when the level is at least n × W, otherwise it changes nothing and returns false. `RetryAfter(now, n)` returns 0 when the level is at least n × W, otherwise S = ceil(N / 1e9) where N = ceil((n × W − level) / limit), and 1 when S is less than 1. For a window, `Take(now, n)` takes n tokens when at least n are available, and `RetryAfter(now, n)` returns 0 when at least n are available and otherwise the same time to the end of the window as before. With n = 1 every method behaves exactly as the old one did, and all of them still refill or move to the current window first.

## Policies, engine and server

A new OPTION, `cost=N`, with N a positive decimal integer of digits only. A bad value or a second `cost=` is `bad option`, and a line may now have up to 9 fields. After all options of a line are read, a cost greater than the policy's `Burst` (which is the limit when no burst is given, and always the limit for a window policy) is also `bad option`, since such a request could never pass.

A matching policy now denies when fewer whole tokens than its cost are available. An allowed request takes the cost of each matching policy from that policy's limiter. `RetryAfter` of a denied request is the largest `RetryAfter(now, cost)` among the denying policies. `Remaining` is still the smallest `Available` after the decision. Replays use costs too, through the engine. In `GET /policies` each object gets a `"cost"` key after `"algo"`.
