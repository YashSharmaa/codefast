# Replaying traffic

Before I deploy a policy file I want to see what it would have done to real traffic. Please add a package that replays a request log against policies, and an endpoint for it.

## Interface changes

```go
// new package replay
type LineError struct { Line int; Msg string }
func (e *LineError) Error() string // "line N: MSG", like policy.ParseError
type Result struct { Line int; Decision engine.Decision }
type Summary struct { Name string; Matched, Denied int }
type Report struct { Requests, Allowed, Denied int; Policies []Summary; Results []Result }
func Run(policies []policy.Policy, log string) (*Report, error) // errors are *LineError
```

New endpoint: `POST /replay`.

## The log

The text is split on `\n` and lines are numbered from 1. Blank lines and lines whose first non-blank character is `#` are ignored. Every other line is split on whitespace into `OFFSET METHOD PATH [OPTION] [OPTION]`, where OFFSET is the time of the request in milliseconds after the start of the log and each OPTION is `user=NAME` or `ip=ADDR` (the value may be empty). The checks, in order, with the first failure reported and nothing replayed:

1. Fewer than 3 or more than 5 fields, an OPTION that is neither form, or the same OPTION twice: `bad line`.
2. OFFSET not a decimal integer of digits only: `bad offset`.
3. OFFSET smaller than the OFFSET of the line before it: `offset goes back`.

## Running

`Run` reads the whole log first. It then makes a fresh engine for the policies with a fake clock and checks each request in order, with the clock set to the start plus OFFSET milliseconds. Requests with the same OFFSET are checked one after the other at the same time. Each request gives a `Result` with its line number and decision. `Requests`, `Allowed` and `Denied` count the requests. `Policies` has one `Summary` per policy in file order, also for policies that never matched: `Matched` counts the requests the policy matched and `Denied` the requests whose decision named it in `Denied`. `Results` and `Policies` are empty (not nil) when there is nothing to report.

## The endpoint

`POST /replay` takes the log as the request body, replays it against the handler's policies (a fresh engine, so the live buckets are not touched) and answers 200 with `{"requests":3,"allowed":2,"denied":1,"policies":[{"name":"api","matched":3,"denied":1}],"results":[{"line":1,"allowed":true,"denied":"","retry_after":0,"remaining":1}]}`, in that key order. A log error gives 400 with `{"error":"line 3: bad offset"}`, the error text of the `LineError`. Any other method on `/replay` gives 405 with an `Allow` header of `POST`, like the other paths.
