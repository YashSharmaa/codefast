# Joins

Next I want to combine tables in one query. Please add joins, table aliases and qualified column names.

## Interface changes

The query grammar of the first version becomes:

```
SELECT items FROM source [join ...] [WHERE expr] [GROUP BY name, ...] [ORDER BY name [ASC|DESC], ...] [LIMIT n]
source := table [[AS] alias]
join   := [INNER] JOIN source ON expr  |  LEFT JOIN source ON expr
name   := column | qualifier.column
items  := * | item, ...        item := expr [AS name] | qualifier.*
```

`JOIN`, `INNER`, `LEFT` and `ON` become keywords. Tables, aliases, qualifiers and columns are names as before, so quoted ones work: `p."first name"`. Column names in expressions, in GROUP BY and in ORDER BY may all be qualified. No Python name changes and the command line needs no change.

## Behaviour

- Each source has a qualifier: its alias if it has one, else its table name. Two sources with the same qualifier are a `QueryError`, so joining a table with itself needs an alias.
- A row of the query is the row of the first source followed by the row of each joined source, in FROM order. Joins apply left to right. `JOIN` (or `INNER JOIN`) keeps each pair of a row so far and a row of the joined table for which ON is `True`. The order is: the rows so far in their order, and for each of them the matching rows of the joined table in table order. `LEFT JOIN` does the same and also keeps each row so far that matched no row, once and at its place, with `NULL` for every column of the joined table.
- ON follows the rules of WHERE: a result that is not a boolean is a `QueryError`, and aggregates are not allowed. ON may use the columns of the sources up to and including the one it joins. A column of a later source is unknown there.
- `q.c` is the column c of the source with qualifier q. An unknown qualifier, or a column that source does not have, is a `QueryError`. A bare `c` is the column c of the one source that has it. When no source has it, or more than one source has it (ambiguous), it is a `QueryError`. This holds for a single table too: `FROM people p` allows `p.name` and `name`, while `people.name` is then an unknown qualifier.
- `SELECT *` lists the columns of all sources in FROM order. `q.*` stands for the columns of source q in table order, as if they were listed one by one (so they count one by one for `colN`). `q.*` in a query with aggregation is a `QueryError`.
- A select item that is a bare column, qualified or not, is named by its column name without the qualifier. Output names may repeat.
- Two names in GROUP BY or in the select list that refer to the same column are the same column, so `GROUP BY city` allows `p.city` outside aggregates.
- ORDER BY: a name without a qualifier is looked up as before (an output column first, else a column of the sources). A qualified name always means a column of the sources, so it works only in a query without aggregation.
- Unknown tables, qualifiers and columns are a `QueryError` even when the tables have no rows.
