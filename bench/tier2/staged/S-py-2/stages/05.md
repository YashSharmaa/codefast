# ParseError, and where an error is

When a long query fails I cannot tell where the problem is. Please rename `QuerySyntaxError` to `ParseError` across the whole project and let errors carry their place in the query text.

## Interface changes

- In `csvq/errors.py`, `ParseError(CsvqError)` replaces `QuerySyntaxError`, which is removed, also from `csvq/__init__.py` (which re-exports `ParseError` instead). Everything said so far about `QuerySyntaxError` now holds for `ParseError`. Update your own tests too.
- `ParseError(message: str, sql: str, position: int)` and `QueryError(message: str, sql: str | None = None, position: int | None = None)`. Both keep the three arguments as the attributes `message`, `sql` and `position`, and have two more, `line` and `column`.
- When `position` is an `int`, `line` is one more than the number of `\n` in `sql` before `position`, and `column` is one more than the number of characters between the start of that line and `position`. So both count from 1. `str(error)` is then `MESSAGE at line L, column C`, with `MESSAGE` the `message` attribute, for example `unknown column 'nope' at line 2, column 8`.
- When `position` is `None`, `line` and `column` are `None` and `str(error)` is the message alone.
- `CsvqError` does not change, and neither does the command line, whose `error:` line now shows the new text.

## Where a ParseError is

A `ParseError` raised by `query` has the query text as `sql`, and `position` is a 0-based index into it:

- An unexpected character: its index. An unterminated string or quoted name: the index of its opening quote.
- Otherwise the first character of the first token that cannot continue a valid query, or the length of the text when the query ends too early. So `SELECT name FROM people;` has position 23, `SELECT count FROM people` has 13 (the `FROM`) and `SELECT name\nFROM` has line 2, column 5.

## Where a QueryError is

These errors about a name carry the query text as `sql` and the index of the name as written as `position` (for a qualified name, the index of its qualifier, and for a quoted name, of its opening quote):

- an unknown table in FROM or JOIN, an unknown qualifier in a column or in `q.*`,
- an unknown or ambiguous column, anywhere in the query,
- a column outside an aggregate that is not a GROUP BY column, and an ORDER BY name that cannot be used,
- an unknown function or a wrong number of arguments (the index of the function name).

Every other `QueryError`, such as a type error, a duplicate qualifier or bad CSV, has `position` `None`, and so do all errors raised by `call_function` itself, which has no query text. A query with only one error reports that one.
