# NULL logic as in SQL

Today every comparison with `NULL` is `False`, so `WHERE NOT age = 25` keeps the rows whose age is `NULL`. I want the three-valued logic of SQL instead, and a few things to write conditions with it.

## Interface changes

- `TRUE`, `FALSE`, `CASE`, `WHEN`, `THEN`, `ELSE` and `END` become keywords. `TRUE` and `FALSE` are literals with the values `True` and `False`.
- New tests `expr IS [NOT] TRUE` and `expr IS [NOT] FALSE`, on the same level as `IS NULL`. Like comparisons they do not chain, so `(age > 30) IS TRUE` needs its parentheses.
- New expression `CASE WHEN cond THEN expr [WHEN cond THEN expr ...] [ELSE expr] END`, a primary like a literal.

## What replaces what

- The first version said that a comparison with a `NULL` operand is `False`, also for `!=`. Now it gives `NULL`. The type rules stay, and `NULL` with any value is never a type error.
- The first version said that `AND`, `OR` and `NOT` need boolean operands. Now they take `True`, `False` or `NULL`. `NOT NULL` is `NULL`. `AND` gives `False` when either operand is `False`, else `NULL` when either is `NULL`, else `True`. `OR` gives `True` when either operand is `True`, else `NULL` when either is `NULL`, else `False`. Both operands are always evaluated, and an operand that is not a boolean or `NULL` is still a `QueryError`.
- WHERE and ON keep a row only when the condition is `True`. `NULL` drops the row like `False`. A result that is neither a boolean nor `NULL` is still a `QueryError`.

## The new expressions

- `x IS TRUE` is `True` when x is `True`, else `False` (also when x is `NULL`). `x IS FALSE` is `True` when x is `False`, else `False`. `IS NOT TRUE` and `IS NOT FALSE` are their negations, so they are `True` for `NULL`. An x that is neither a boolean nor `NULL` is a `QueryError`.
- `CASE` evaluates the WHEN conditions in order and gives the THEN value of the first one that is `True`. A `NULL` or `False` condition is passed over. When none is `True` it gives the ELSE value, or `NULL` without ELSE. A condition that is neither a boolean nor `NULL` is a `QueryError`. Only the conditions up to the chosen one and the chosen value are evaluated, so `CASE WHEN TRUE THEN 1 ELSE -name END` is 1 even when `name` holds strings.
- Two booleans may be compared with `=`, `!=` and `<>`. Any other comparison of a boolean (with `<`, or with a number or a string) is a `QueryError`.
- A `CASE` may hold aggregates, and with aggregation its columns outside aggregates must be GROUP BY columns, as for any expression. A `CASE` is named `colN`.
- A `NULL` result of a comparison prints as an empty field and sorts first, like any `NULL`.
