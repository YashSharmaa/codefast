# Targets and variables on several lines

I often split the dependencies of a target over several lines, as make allows, and buildplan rejects that with `duplicate target`. Please change this, and let me append to a variable as well.

## What changes

The error `duplicate target "NAME"` from the first version goes away. A target line whose name is already declared no longer fails. It adds to the target that is already there:

- Its dependencies are appended to the target's list. A name already in the list, from any of the target's lines, is kept only at its first position.
- The indented lines after it are commands of that target, appended to the commands it already has.
- Commands may follow only one of a target's lines. A command line that follows a line of a target which already has commands from another of its lines gives the error `duplicate commands for "NAME"` (Go `%q` quoting), reported on the line of that command.
- The target keeps the place in `File.Targets` and the `Line` of its first line.

The dependency text of every target line is now expanded, so `a:` followed later by `a: $(UNDEFINED)` gives `undefined variable "UNDEFINED"` on the later line.

Everything that reads a target sees the merged one: `graph.FromFile` adds the edges in the merged dependency order, and the automatic variables `$^` and `$<` use the merged list, since they are replaced after the whole file is parsed. Pattern rules are not affected: a second rule with the same pattern is still the error `duplicate rule "PATTERN"`.

Example: the target line `app: main.o` on line 1, the command `ld $^` on line 2 and the target line `app: util.o main.o` on line 5 give one target `app` with `Line` 1, dependencies `main.o util.o` and the command `ld main.o util.o`. A command on line 6 would instead fail with `line 6: duplicate commands for "app"`.

## Appending to variables

A line made of a name, optional spaces or tabs, `+=` and a value is now an assignment that appends. The value is everything after the `+=` with surrounding whitespace removed, expanded at once as for `=`. When the variable has no value yet, or its value is empty, it gets the expanded value. Otherwise, when the expanded value is not empty, the new value is the old value, one space and the expanded value, and when it is empty the old value stays. For example `SRC = a.c`, then `SRC += b.c`, then `SRC +=` leave `SRC` as `a.c b.c`. A line such as `X+=a:b`, which used to be a target line, is now an assignment.
