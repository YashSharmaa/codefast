# Pattern rules for goals

`plan Buildfile mtimes extra.o` does not use the `%.o` rule, because pattern rules only apply to dependencies of declared targets. I want goals to get rules too, so the graph has to know the goals.

## Interface changes

```go
// package graph, replaces FromFile(f *parse.File) *Graph
func FromFile(f *parse.File, goals []string) *Graph
```

Every caller passes its goals: `plan.Make` passes the goals it got from `DefaultGoals`, the `order` command passes the goals it got from `DefaultGoals`, `waves` passes what `plan` passes, and `cycles` passes nil. With nil or empty goals the graph is exactly what it was before. Update your own tests too.

## Behaviour

After its two passes over the declared targets and their dependencies, `FromFile` takes the goals in the given order. A goal that is not a declared target, did not get a rule's edges in the second pass, was not handled earlier in this goal pass, and that `Resolve` makes a target from, is added with `AddNode(goal)` and then `AddEdge(goal, dep)` for each dependency of that target in order. This holds even when the goal is also a dependency of a target made from a rule. A goal that no rule matches is not added, so `Order` still treats it as a node without dependencies. The dependencies of a goal's target are not matched against the rules.

`plan.Make` plans a goal that got a rule like any other target made from a rule: it runs for the same reasons, with its own commands, and it counts as a target for `NeededBy`. Example: with `%.o: %.c` and the goal `extra.o`, the order is `extra.c extra.o`, `extra.o` runs with the reason `missing` when it does not exist, and a missing `extra.c` now gives `missing "extra.c" needed by "extra.o"` instead of `missing "extra.o"`.
