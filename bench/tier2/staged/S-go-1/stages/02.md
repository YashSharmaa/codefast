# Pattern rules, automatic variables and phony targets

Writing one rule per object file is getting tedious, and `clean` only runs when no file of that name exists. Please add three things from make: pattern rules, automatic variables in commands, and phony targets.

## Interface changes

```go
// package parse
type Rule struct { Pattern string; Deps []string; Commands []string; Line int }
type File struct { Vars map[string]string; Targets []*Target; Rules []*Rule; Phony []string } // Rules in declaration order
func (f *File) Resolve(name string) *Target
```

## Parsing

A target line whose expanded name contains `%` declares a pattern rule instead of a target. The name must contain exactly one `%`, otherwise the error is `bad line`. A second rule with the same pattern gives `duplicate rule "PATTERN"` (Go `%q` quoting) on the later line. Its dependencies are read as for a target, the indented lines after it are its commands, and `Line` is its line number.

## Automatic variables

In a command, after the `$(NAME)` expansion, one more left-to-right pass replaces `$@` with the target name, `$<` with its first dependency, `$^` with all its dependencies joined by one space, and `$*` with the stem (see below). `$<` and `$^` are empty for a target without dependencies, and `$*` is empty for a declared target. Every other `$` is kept as it is. This pass also sees the text that the expansion put in, so a variable whose value contains `$@` gives the target name. For a declared target this pass runs once the whole file is parsed, so `Target.Commands` hold the final text. `Rule.Commands` keep the automatic variables until the rule is used.

## Using rules

A pattern `P%S` matches a name that starts with P, ends with S and has at least one character in between, the stem. `Resolve` returns the declared target of that name when there is one. Otherwise it returns a new `*Target` made from the first rule, in declaration order, whose pattern matches: `Name` is the name, `Deps` are the rule's dependencies with every `%` replaced by the stem (a repeated name kept only at its first position), `Commands` are the rule's commands with the automatic variables replaced, and `Line` is the rule's line. With no match it returns nil.

Rules apply only to dependencies of declared targets, not to names given as goals, and the dependencies of a target made from a rule are never matched against the rules again. `graph.FromFile` first adds the declared targets exactly as before. Then it takes the nodes that this first pass added and that are not declared targets, in node order, and for each one that `Resolve` makes a target from, it calls `AddEdge(name, dep)` for each of that target's dependencies in order.

`plan.Make` plans a target made from a rule like a declared target, with the same reasons and its own commands in the step, and such a target counts as a declared target when `NeededBy` of a `MissingError` is chosen. The command line needs no change.

## Phony targets

A target line whose expanded name is `.PHONY` declares its dependencies phony instead of declaring a target. There may be several such lines. `File.Phony` lists the phony names in the order they were first named, without repeats. An indented line whose most recent target line is a `.PHONY` line gives `commands for .PHONY`, even when no target has been declared yet. Once the whole file is parsed, every phony name must be a declared target, otherwise the error is `phony "NAME" is not a target` on the `.PHONY` line that first named it (the first such name in `File.Phony` is reported). In `plan.Make` a phony target always runs, with the reason `phony`, checked before the other three rules, and its own modification time is never looked at.
