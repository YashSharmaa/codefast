# Bug: a `#` later in a line is not a comment

With this build file:

```
CC = gcc   # the compiler
all: app   # the default goal
app: main.c
	$(CC) -o app main.c
```

`order` prints `main.c`, `app`, `#`, `the`, `default`, `goal` and `all`, `plan` fails with `missing "#" needed by "all"`, and the command of `app` is `gcc   # the compiler -o app main.c`. It should work as in make: `order` should print `main.c`, `app` and `all`, and the command should be `gcc -o app main.c`.

## What changes

On a line that is not blank, not a comment line and not indented, everything from the first `#` to the end of the line is removed before the line is classified, and then surrounding whitespace is removed as before. This applies to assignments, target lines and pattern rule lines. So:

- `X = a#b` sets X to `a`, and `X = # nothing` sets X to the empty string.
- `all: a b # main` has the dependencies `a` and `b`, and `all: # none` has none.
- A reference after the `#` is never expanded, so `all: x # $(UNDEFINED)` is not an error.
- `app # : x` becomes `app`, which is a `bad line`. Line numbers in errors stay the same.

Indented lines are not changed: a `#` inside a command is kept, since it belongs to the shell. An indented line whose first non-blank character is `#` is still a comment line and is ignored.

The MTIMES file gets the same rule: everything from the first `#` on a line is removed before the line is read. So `main.c 10 # edited` is the pair `main.c 10`, a line that is empty after that is ignored, and `main.c # 10` is `mtimes line N: bad line`.
